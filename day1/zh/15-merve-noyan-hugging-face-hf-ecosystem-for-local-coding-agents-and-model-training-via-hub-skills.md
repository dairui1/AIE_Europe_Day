# Merve Noyan (Hugging Face)：用于本地编程 Agent 的 HF 生态系统，以及通过 Hub Skills 进行模型训练

大家好，欢迎来到这场关于开放 Agent 生态系统的演讲。我想把它命名为"让 AI 工程师触手可及"。我是 Merve，在 Hugging Face 开源团队工作。在座有多少人每天都在使用 Hugging Face？哦，我们要改变这个现状，这样不行。

先来聊聊开源及其含义。在机器学习领域，开源绝对是有差异化价值的。你有开放权重模型（open weight models），通常带有非商业许可证，我们称之为"开放权重"。然后是开源模型，带有可商用的许可证，比如 MIT 或 Apache 2.0，deepseek 就是例子。还有更开放的模型，连代码都是开放的——如果其中有 Agent，运行框架是开放的，一切都是开放的。这一点格外重要，因为就在前几天有消息说 Claude 的性能在下降。如果你拥有一切透明的东西，你不知情的情况下什么都不会改变，也不会有你不知道的性能退化，一切都很好。此外，如果你能访问模型权重，你可以对其进行压缩、量化和微调。并且对终端用户而言，这绝对保证了隐私，因为你可以将其部署到边缘设备和浏览器，而数据不会发送到其他地方。在当今这个安全漏洞频发的时代，这一点在我看来比以往任何时候都更重要。

曾经有人说开源模型不如闭源模型优秀，这种说法现在完全站不住脚。比如最新的 GLM 5.1 表现极为出色，我实际上在我的编程设置里就在使用它。这是 Artificial Analysis 智能指数，绿色的是开源模型，黑色的是闭源模型，我们已经赶上来了，随着即将推出的模型，我们还会继续追赶。

回到 Hugging Face Hub，一切都通过它来实现，所有的开放发布都经由 Hub。它是所有开源工作流的基础设施层，目前托管的模型数量已接近 300 万，还有大量数据集、Spaces 等。但在 Agent 生态系统方面，这还不是全部，这正是我们今天要讲的内容。

你可以在模型页面筛选 agentic 模型，其中大多是热门模型，大致分为两类：视觉语言模型（VLM）和纯文本 LLM。VLM 可以通过截图充当计算机使用 Agent，知道在哪里点击等，相当酷。我最近注意到一个趋势，各家实验室在发布 LLM 时，从第零天起就带有视觉能力，比如 Gemma 4 是一个全能模型，同时也是一个 agentic 模型；还有 Qwen 2.5、Kimi 2.5，这些都是 VLM。我预计未来所有模型都将从发布第一天起就具备视觉能力。运行这些模型其实非常简单，只需几行代码，比如使用 vLLM、llama.cpp 的 llama server 等，比以前方便多了。

如果你想比较开源模型，我们最近推出了一个叫"基准数据集"的功能。在 Hub 数据集页面的左侧底部，有一个 benchmark 按钮，点击后可以看到流行的基准测试，如 SWEBench Pro、Humanity's Last Exam、AIME 等。比如进入 SWEBench 查看你的 Agent 在编程方面的表现，你会看到按分数排名的开源模型，目前 GLM 5.1 排在首位。现在挑选开源模型也变得更容易，尽管有 300 万个模型，不好选择也是曾经的挑战。

如果想快速验证，Hugging Face 有一个叫 Inference Providers 的服务，负责将最好的模型路由到最佳提供商，包括 Groq、Cerebras、Novita 等，比较也很方便。有最便宜或最快的选项，还有工具使用（tool use）列，可以专门为 agentic 场景挑选开源模型。

Hugging Face Hub 最近推出了大量针对 Agent 的新功能：有 MCP 服务器，可以将 Hub 接入你的 LLM；有 Skills（技能），甚至允许你直接训练模型——你只需对 Agent 说"帮我在这个数据集上训练 Qwen 2.5"，它就会训练，对我来说这简直是科幻，因为以前根本不存在；还有本地 Agent，可以用集成了 Hugging Face Hub 的模型在本地运行完整的编程 Agent。我今天的演讲将围绕这些内容展开。

首先是本地编程 Agent 及其选项。你有很多选项，我最喜欢的是 Pi，因为设置超级简单。你可以用它远程接入 Inference Providers，也可以用 llama.cpp 在本地部署，Pi 会直接消费它。还有一个很酷的 llama agent，作为二进制文件内置于 llama.cpp 中，只需给定 Hugging Face Hub ID 就可以直接启动模型，非常方便。我的幻灯片之后会分享到我的 Twitter 账号，不需要拍照。

我最近最喜欢的一个工具是 Hermes agent，我会坚持这个立场。它在记忆管理等方面比 OpenClaw 更进一步，上手也超级简单，可以在本地使用或通过 Hugging Face Inference Provider 使用。设置向导会帮你搞定一切，只需输入密钥，然后集成到 Slack 或 WhatsApp 等即可。我绝对推荐配合开源模型使用——我强烈推荐 GLM 5.1，我一开始集成到 Slack 时失败了，有目击证人，我的同事 Niels 就在这里，我让 GLM 5.1 配合 Hermes agent 来修复，它自己就修好了，那是美好的一天。我迫不及待想用 Gemma 4 来使用它，据 Twitter 传言还有 MiniMax 的新模型要出，我也会尝试并分享结果。

另外，Hugging Face Hub 现在有了一种新的数据集仓库类型叫做 Traces（轨迹）。这会托管你的 Codex、Claude Code 或 Pi 的轨迹数据。如果你推送了一个轨迹，进入数据集查看器，点击 traces 列，它会这样弹出，解析得非常漂亮，可以直接浏览数据，之后还可以用来训练模型。如果你想推送 Agent 轨迹，只需从这些路径上传会话即可。Hermes agent 的轨迹支持也很快会上线。

如果想要更多本地 LLM 服务选项，有一些技巧：去 Hugging Face，点击"其他"标签，下面有 Apps，这些就是本地服务工具，比如 LM Studio、Jan、llama.cpp 等，按它们筛选就能找到支持的模型。进入模型仓库后，左侧有 GGUF 区——GGUF 是 llama.cpp 支持的文件格式，也受到 LM Studio 等众多工具支持，还有硬件兼容性信息。比如 Gemma 4 的较大模型量化到 4bit 后可以放进 24GB 显存的 L4 GPU，这也适用于 MLX 仓库。在模型仓库右上角还有"使用此模型"按钮，会显示支持该模型的本地应用，点击后只需几行命令就能安装并启动服务。

最后，用 Hugging Face Skills 为你的编程 Agent 加速。我们有一批 Skills 帮助你开始训练，推理开放模型，探索开放数据集，使用 AI 应用等。Hugging Face CLI skill 允许编程 Agent 管理仓库、运行任务、启动演示等，安装方法如下，在 Google 搜索 HF skills 就能找到命令。但我们还有更多 Skills：LLM Trainer Skill 不仅支持 LLM，也支持视觉语言模型，只需告诉模型"帮我在这个数据集上训练这个模型"，它就会在我们的基础设施或本地启动任务；Gradio skill 允许你构建演示；Hugging Face Dataset Skill 允许通过数据集查看器 API 探索数据集。我们还支持 Claude 和 Gemini 的集成。

实际操作举例：我让 Claude Code 说"帮我在 LLaVA-Instruct-Mix（一个视觉语言数据集）上微调 Qwen2-VL"，它问了我几个问题，比如选择哪个实例，因为有多个选项——Agent 会在后台计算在给定批量大小下微调该模型所需的显存量，处理好一切。它问几个问题，比如验证集切分比例等，然后就启动任务了。对于一个从职业生涯开始（大约六年前）就在训练模型的人来说，这绝对还是科幻感十足。你最终在 Hub 上找到你的模型，而且不仅限于 LLM 和 VLM，我最近还为目标检测、图像分割等视觉任务发布了 skills，处理不同的边界框类型等，你只需给出命令，让它处理一切。

回到 MCP，我们提供模型、数据集、Spaces 搜索、任务语义搜索——Spaces 是 AI 的应用商店，有各种各样的应用，简直应有尽有。我们还有 Jobs 功能，允许你启动一次性任务，成功或失败后结束，按运行时间计费。也可以从 MCP 查询这些应用，与你喜欢的平台集成都很顺畅。比如让模型"生成一张用纱线做成的 Baklava 图片"，它会调用托管在远程的 Hugging Face 图像生成模型 qwen-image，返回图片结果，效果非常好。记得在 MCP 设置中开启 dynamic spaces 选项，如果你想要更多 Spaces 选项的话（该功能还是实验性的）。

最后，我的同事 Niels 做了一件我觉得很酷的事。Hugging Face Hub 上有论文，是 AI 相关论文，我们希望人们能够对这些论文提问或分享，但并非所有论文都带有可供索引的 Markdown 格式。所以我们用 Codex、开源 OCR 模型和 Jobs，全部通过提示词驱动，对 30,000 篇论文进行了 OCR 处理。步骤如下：首先挑选一个成本低且性能好的 OCR 模型，然后让 LLM 编写处理任务的代码并在 Hugging Face 基础设施上启动，让 skill 自动搭建托管实例，省去了手工估算的痛苦。

要挑选 OCR 模型，可以去 ALM OCR Bench（一个基准数据集），第一条结果是 Chandra OCR，但今天我们刚上线了一个 skill，你可以直接问模型"OCR 任务中用于微调的最佳模型是什么"，它还会给出微调建议，如果需要更小的模型等，一切都会处理好。我们使用了 Chandra，让模型编写脚本，Agent 估算实例大小，计算运行成本，然后这些任务会被重新运行。我们最近推出了一个叫做 Buckets 的基础设施产品，类似于 S3 但更便宜更快，支持挂载，使用非常简单。

希望你喜欢这个演讲，非常感谢大家。
