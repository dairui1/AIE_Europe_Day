# Omar Sanseviero（Google DeepMind）：Gemma 4 的端侧能力与 E2B 架构

开放模型（open models）意味着这些模型可以被下载、可以在你自己的基础设施和设备上运行、可以针对你的用例进行微调。大约一年前，我们发布了 Gemma 3。那时，Gemma 3 是能够在单块消费级 GPU 上运行的最强开放模型。我们设计了从 10 亿参数到 270 亿参数的一系列模型。彼时它在 LM Arena 排行榜上表现非常强劲。这里你可以看到不同开放模型在 LM Arena 上的得分，底部的小点代表加载这些模型所需的 H100 或 A100 数量。这是一年前的 Gemma 3，即便如此，你可以看到，即便是一年前的模型，一个小巧而相对轻量的模型，其能力也极为出色。好了，上周我们发布了 Gemma 4，这也是我第一次在大会上介绍 Gemma 4，非常激动。

Gemma 4 是 Google 迄今发布的能力最强的开放模型家族，参数规模从 20 亿到 320 亿不等。这些模型各具特色，我来逐一介绍。你可能注意到有个字母"E"，我稍后也会解释。其中最小的两款模型可以直接在 Android 手机、iOS/iPhone 以及 Raspberry Pi 上运行——这些是非常、非常小的模型，具备多模态能力和推理能力，可以在端侧完成非常酷的 agentic（智能体）任务。接着是一个混合专家（mixture of experts）模型，速度极快、延迟极低，能做很多有趣的事情。然后是 31B 的最强、最聪明的模型——当你需要最强的原始智能时，就用这款大模型。但即便是 31B，也能在消费级 GPU 上运行。这些模型的尺寸都对开发者非常友好，这对我们来说非常重要。

下面让我展示几个演示——假设视频能顺利加载的话。这里有很多内容，我从右边那个开始介绍。右边是一个应用，Gemma 直接在 Android 手机上运行，可以选择不同的技能（skills）。这是一个完整的 agentic 设置，模型可能在讲解一个弹钢琴的技能，然后 Gemma 就真的弹起钢琴来了。左边是 Gemma B 在端侧进行编程，同样是飞行模式，没有任何 API 调用，完全在手机上运行。中间那个例子是在笔记本电脑上，并行运行了 20 个——不对，10 个 Gemma 实例，每个都在执行不同的 SPG（结构化程序生成）任务，几秒钟后你就能看到 10 个由不同 Gemma 智能体生成的 SPG。所有这些都在端侧借助 llama.cpp 运行，速度达到每秒约 100 个 token。你能看到这 10 个 Gemma 模型生成的 SPG。Gemma 是一款优秀的编程模型，支持 agentic 任务、编程，甚至 Android 应用开发，而且全程离线。

LM Arena 的得分相当不错。这里你可以看到各种模型：横轴是参数量（十亿），纵轴是 LM Arena 得分。LM Arena 并不是完美的基准，但它能反映社区对模型在通用场景（如对话等）的偏好。Gemma 在友好、有帮助与高能力之间取得了很好的平衡。你能看到左上角的那个区域，代表着这些模型体积非常小但能力极强，令人振奋。过去两年，模型的进步令人称道：去年是 Gemma 3，两年前是 Gemma 2（对不起，是 Gemma 1，不对，是 Gemma 2）。在各种任务上，模型不断变强，却没有变大，这对我来说非常令人兴奋。如果想想一两年后我们会在哪里，我相信届时我们的口袋里就有极其强大的模型直接在设备上运行。我会跳过基准测试部分，总之令人兴奋的是 Gemma 可以在台式机、笔记本和手机上运行。我前两天看到有人把 llama.cpp 装进了 Nintendo Switch，并在上面试用 Gemma。不知道几年后会是什么景象，但我对此充满期待。

之前 Gemma 版本中，我们收到很多关于许可证不够好的反馈——大家希望有一个真正意义上的开源许可证。因此，Gemma 4 将许可证改为正式的 Apache 2 许可证，赋予你充分的灵活性。这也是一个很大的改进。

你可能听说过混合专家（27B/26B 模型）和 Transformer 架构，但你可能从未听说过那个"E"。E2B 代表"有效 20 亿参数"（effectively two billion parameters）。实际上 Gemma E2B 有更多参数，大约 40 亿，并采用了一种名为"逐层嵌入"（per-layer embeddings）的全新架构，这是我们去年夏天发布的。底部有一个小模块，简单来说，每一层都有一个独立的嵌入——正如其名——它更像一个查找表，而不是需要执行的计算。因此速度极快，不需要放在 GPU 上，可以放在 CPU 上，甚至可以放在磁盘上。这是一个专门针对端侧（如移动）场景优化的架构决策，这就是为什么能在 Android 或 iPhone 上运行的最小模型采用了这种 E2B 或 E4B 架构。即便模型有 50 亿参数，你实际上只需要将 20 亿参数加载到 GPU，其余部分可以放在速度较慢的存储介质中，因为你不需要像 Transformer 架构那样执行矩阵乘法。可以通过 llama.cpp 的一个简单标志 `override tensor` 来实现，将逐层嵌入移到 CPU 甚至磁盘上，开箱即可良好运行。

还有一些令人兴奋的特性：最小的模型支持图像、视频甚至音频的多模态理解，可以做语音识别、语音转文字翻译——比如我说西班牙语，文本可以被转录成法语。更大的模型则拥有极强的多模态理解能力，支持视频和精细细节分析。我这里有几个示例：可以在图片中指出 llama（羊驼）的位置，可以做目标检测，识别图片中的不同物体。更酷的是，这个模型具有很强的多语言能力——Gemma 4 在超过 140 种语言的数据上训练，使用了基于 Gemini 的分词器（tokenizer）。Gemini 背后所有的多语言研究同样赋能了 Gemma。分词器的设计尤其有趣：即便不考虑 Gemma 的原始能力，这个分词器本身就是为多语言场景精心设计的。这意味着，如果你想针对数字资源匮乏的语言（比如秘鲁的 Quechua 语，或者印度的某种官方语言）微调 Gemma，你可以使用自己的数据训练，仅凭分词器的设计，就能开箱即用地取得相当不错的效果。你还可以将多语言与多模态能力结合，例如为包含日文文字的图片生成解释。

我们一周前发布了这款模型，昨天 Gemma 4 系列模型的下载量就突破了 1000 万。基于 Gemma 4 的模型已经超过 1000 个（包括社区的量化版本和微调版本），整个 Gemma 家族的总下载量超过 5 亿次。对我而言，最令人高兴的是，Gemma 不仅仅是一个"可以使用的模型"，更是支持整个生态系统在其上构建的基础，而这正是过去几天社区所做的事情。它登上了 Hugging Face 热门榜首，人们基于它构建了各种酷炫示例，Unsloth 团队也用 Gemma 完成了整个代码库的审计，人们把 Gemma 装进各种设备，探索它的各种能力，非常令人欣慰。

而且这一切并非我们单打独斗——我们与开源生态系统密切合作，携手 Unsloth、MLX、Ollama、Hugging Face、BLM、silang 等，确保每当我们发布 Gemini 或 Gemma 的新工具，大家都能开箱即用。比如用 Hugging Face transformers 微调 Gemma 的用户，不需要为此切换到 PEFT 或其他框架。对我们来说，在社区所在的地方扎根非常重要、非常关键。因此，向所有为开源生态系统做出贡献的人，向这些代码库的维护者，致以由衷的感谢，正是因为你们，整个生态才得以做出令人惊叹的事情。

Gemma 还有一个让我喜欢的方面，就是各种产品集成。Android Studio——不知道在座有没有 Android 开发者——Android Studio 现在有了 agent 模式，有一个智能体帮助你编写代码和开发应用。现在还有离线模式，可以使用 llama.cpp 或 Llama 或 BLM 驱动的系统，让 Gemma 帮你进行 Android 开发，我们在训练 Gemma 时也确实加入了一些 Android 相关的数据集和基准，所以它在 Android 开发方面是一款非常有竞争力的模型。

我谈了很多关于微调和分享的内容，现在让我来分享一些 Gemma 的数字。这个数字已经过时了，这是上周的数据，现在已经有 5 亿下载量了。整个 Gemma 家族拥有超过 100,000 个模型变体。也许你只是想开箱即用——对于很多场景来说，开放模型可能已经完全够用了；但也许你想提升模型能力，想改变模型与用户交互时的风格，或许你不需要一个对话型模型，只需要一个能在特定上下文中预测某些事物的模型，又或者你家里有太多 GPU 需要烧掉……不管出于什么原因，你都可以为各种有趣的用途微调模型。

Google 官方也做了几个 Gemma 变体，我们称之为 "official Gemma variants"（官方 Gemma 变体）。Shield Gemma 是一组内容安全模型，非常适合生产场景——当你不希望用户输入有毒图像或违反内容政策的文字时，Shield Gemma 就是用于此目的的模型家族。还有其他使用场景，例如在医疗领域，我们发布了 Med-Gemma——一个基于 Gemma 3 的多模态医疗任务模型，涵盖放射学、胸部 X 光理解等多种任务。这些同样是开放模型，可以直接使用，也可以针对更细分的用例进一步微调。

社区也在做很酷的事情。例如 AI Singapore，他们是一个为东南亚语言训练模型的团队，他们基于开放模型开展了大量研究，进一步推动多语言能力的前沿。又如 Sarvam——印度有很多官方语言，政府正在支持几家初创公司训练国家模型，这更多地涉及主权 AI 和官方语言的视角，但人们在多语言方面正在做非常有趣的事情。

除此之外，还有很多其他酷炫的研究。比如我们去年 12 月发布的一篇论文，DeepMind 的研究人员使用 Gemma 3 提出了一些癌症治疗路径，这些路径随后被带入实验室进行验证，结果证明这个基于 Gemma 的模型所提出的路径确实能够产生可验证的实际结果。这非常令人振奋，因为这不仅仅是让助手帮你聊天或角色扮演——而是构建能够真正帮助社区的模型，无论是金融、法律审查，还是不希望数据离开服务器的离线场景，地铁里或飞机上需要用 AI 的场景，想要在 Chrome 扩展中内嵌 Gemma 来理解屏幕内容，或者端侧控制……开放模型正在走向这一切。

对我而言，这非常令人兴奋，因为与一两年前相比，如今的开放模型已经能够完全在端侧、在你的手机上执行非常酷、非常有趣、高度 agentic 的复杂任务了。我真诚建议大家在接下来两周内花一个小时，玩一玩最新的开放模型，了解一下它们的能力。当然，对于很多场景，你可能仍然会选择基于 API 的模型；如果你需要最强的原始智能，你会去使用 Gemini 或你偏好的其他模型。但如果你想要端侧运行，现在已经有很多令人兴奋的事情可以做。对我来说，最令人期待的是，我不知道六个月或十二个月后会是什么景象，但我认为我们正在朝着一个非常令人兴奋的方向前进：人们将能够在自己的设备上，用自己的数据，拥有针对自己用例定制的极其强大的开放模型。所以，请大家去试试这些模型，构建一些东西，并且分享出来。谢谢！
